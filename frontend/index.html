Five hops, one report

tunnel Cloudflare Tunnel outbound only, no inbound ports

What runs where

The page

Static HTML, one stylesheet pair and module scripts, no framework. The app page carries the analyzer form and the report renderer; the form posts url plus a list of category checkboxes to /api/analyze. Everything the page shows comes back in one JSON response, so a run has no hidden state: render, store in localStorage history, done.

The edge

A Cloudflare Pages Function sits between the page and the adapter. It validates the URL the same way the adapter does (identical denylist, two copies by contract) and answers 422 for reserved and private-network targets before the request leaves Cloudflare. It forwards, it never analyzes: the Workers CPU cap would not allow it, and compute is not its job.

The tunnel

The adapter never opens a port to the internet. cloudflared dials out to Cloudflare, and the Pages Function reaches the adapter through that one outbound connection. The tunnel URL is written into the project secret automatically, so a tunnel restart does not silently orphan the live site.

The adapter

A Node http server on the VM. It compares the x-api-key, starts a 70s deadline, and runs the four requested categories concurrently. Every outbound fetch goes through one guard: redirect: manual, at most 3 hops, re-resolved and re-checked against the denylist at every hop. A category that fails becomes a limitation in the verdict, never a failed request.

The engine

Four categories, two engines. Fingerprint reads response headers, framework markers, CDN hints and TLS in its first pass. JS bundles inventories the page's scripts (up to 40 bundles, 1MB each, 10s per fetch) and reports entrypoints and endpoints. Browser capture and JS deep analysis are handled by the REA engine: a bounded capture scenario, and a static parse of up to 5 downloaded bundles (2MB each) through analyze-javascript-application.

What you get back

One JSON document per run. Every finding carries its own evidence, and the verdict carries what the engine could not see. The app renders exactly that shape, nothing narrated around it. 

{
  "status": "ok",
  "findings": {
    "url": "https://example.com/",
    "timestamp": "2026-10-19T05:14:09.581Z",
    "fingerprint": { "findings": [ ... ], "cdn": "Cloudflare", "tls": null },
    "js_bundles": [ ... ],
    "browser_capture": null,
    "js_deep": { "files_analysed": 1, "findings": 0, "confidence": "derived", ... },
    "verdict": {
      "confidence": "high",
      "limitations": [ "..." ],
      "unknowns": [ "..." ]
    }
  },
  "duration_ms": 66276
}
  • type is observation, derivation or the rare inference: never a score.
  • confidence is how good the evidence is, not how safe the site is. reascan refuses to grade websites.
  • A failed category lands in limitations; an unobservable answer lands in unknowns. Nothing is dropped silently.
  • Secret-pattern detection is intentionally absent: the report can never display a secret value.
